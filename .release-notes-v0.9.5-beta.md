## v0.9.5-beta — 2026-05-10

Animal Crossing: New Leaf reaches near-complete icon coverage, the hand-drawn icon library grows to seven pieces, and a handful of polish nits close out tracked issues.

### What's new

**ACNL icon gap-fill — 96.5% coverage**
135 items scraped from the Animal Crossing Fandom wiki (23 fish + 28 bugs + 34 fossils + 18 art + 32 sea creatures) via the established Fandom MediaWiki + algorithmic-resolver-plus-`OVERRIDES` pipeline. ACNL goes from 49.1% to 96.5% coverage (275/285). Ten items with no workable Fandom page are logged to `scripts/missing-acnl.txt` and fall through to the existing monogram placeholder — the same graceful treatment used for accepted gaps in other games.

As a side effect of cross-game ID routing introduced in v0.9.2, ACCF reaches 100% coverage (155/155) at no extra cost, and ACNH rises to 68.8% (227/330) ahead of its dedicated gap-fill beta.

**Three new hand-drawn icons**
- Frog (`fish/frog.png`) — fifth hand-drawn piece, replaces the scraped wiki asset. 2048×2048 Procreate source, optimized to 148 KB at 768×768
- Robust cicada and brown cicada (`bugs/robust-cicada.png`, `bugs/brown-cicada.png`) — sixth and seventh hand-drawn pieces, replacing scraped Fandom placeholders. 68 KB each at 768×768

The hand-drawn library now covers: sea-bass, koi, coelacanth, frog (fish); ant, robust cicada, brown cicada (bugs).

### Behind the scenes

**Resolver improvements (PR #127)**
Two targeted changes to `scripts/lib/icon-resolver.ts` that generalize beyond ACNL: `c:search` results now deprioritize `/Gallery` subpages so the parent article is tried first (the gallery remains a fallback when it's the only image source); `sea_creatures` entries get a `deep-sea creature` disambiguation step for ACNL/ACNH items whose names collide across categories. Both changes will benefit the ACNH scrape in v0.9.6.

**Polish nits (PR #130, closes #124, #95, addresses #92 item 4)**
- `version-history.html` velocity headline corrected (25 days → 29 days)
- `useIconChecker` closure wrapped in `useMemo` — prevents a new function allocation on every render
- `vi.unstubAllGlobals()` added to `ItemIcon.test.tsx` `afterEach` — `vi.restoreAllMocks()` alone does not clean up `vi.stubGlobal` calls, so stubs could leak between test files

Lint debt note: 565 pre-existing ESLint problems on `development` were confirmed unchanged by this release's code changes. Tracked as issue #132 for a future dedicated sweep.
